Sign in to your account

Many networks let you register your nickname as an account. Glasstual signs in with SASL as it connects, before it joins any channel.

Set up sign-in

  1. Select the server, then choose Server > Server Properties, then click Identity.
  2. Under Authentication, select Sign in with SASL.
  3. Enter your account name and password. The password is stored in your keychain.
  4. Choose a SASL mechanism, or leave it on Automatic to let Glasstual pick the strongest one the server offers.
  5. Click Save, then reconnect.

If you turn off SASL, Glasstual uses the password to identify with NickServ instead.

SASL mechanisms

PasswordSends the account name and password (PLAIN).
Password ProofProves you know the password without sending it (SCRAM-SHA-256 or SCRAM-SHA-512).
Client CertificateSigns in with the certificate chosen in the Client Certificate pane (EXTERNAL).
Signing KeySigns the server’s challenge with an ECDSA key stored in your keychain (ECDSA-NIST256P-CHALLENGE).
OAuth TokenSends a bearer token, only over an encrypted connection whose certificate is trusted (OAUTHBEARER). Paste a new token when it expires.

On Automatic, Glasstual tries a certificate or key first, then a token, then a password proof, and the plain password last. Select “Use only this mechanism” to stop Glasstual from trying the others. If the details a mechanism needs are missing, the pane says so.

Use a signing key

  1. In the Identity pane, click Generate Key, or click Import to use an unencrypted P-256 private key in PEM or PKCS #8 format.
  2. Click Copy Public Key, then register it with your account, for example with NickServ SET PUBKEY on Atheme networks.
  3. Choose Signing Key as the SASL mechanism.

The private key stays in your keychain.

Sign in again

To sign in again without reconnecting, for example after services return, choose Server > Sign In Again, choose a mechanism if you want a particular one, then click Sign In. In the Identity pane, select “Sign in again when services return” to have Glasstual do this on its own.

You can also type /sasl status to see how you’re signed in, or /sasl auth to sign in again.

Choose what happens around sign-in

In the Authentication section of the Identity pane:

  • Select “Wait for identification before joining channels” so channels that need an account don’t refuse you.
  • Select “Disconnect if SASL authentication fails” to stay off the network rather than connect without your account.
